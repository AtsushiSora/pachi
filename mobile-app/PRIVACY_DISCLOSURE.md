# ストア向けデータ取扱いメモ

Google Playのデータセーフティ、App Storeのプライバシー申告で使うための整理メモです。
実際の申告時は、AdSense / AdMob / Supabaseの最新設定とストア画面の選択肢に合わせて確認します。

## 基本方針

- 本名、住所、電話番号、メールアドレスの登録は不要
- ランキング登録はニックネームで行う
- ニックネームには個人情報を入れないよう登録画面で案内する
- 実際の金銭取引、景品交換、賭博機能はない
- 広告配信にはGoogle AdSense / AdMobを使う

## アプリが扱うデータ

| データ | 用途 | 保存先 | ユーザー入力 |
| --- | --- | --- | --- |
| ニックネーム | ランキング表示 | Supabase | あり |
| スコア | ランキング表示 | Supabase | なし |
| 連チャン数 | ランキング表示 | Supabase | なし |
| 初当たり回転数 | ランキング表示 | Supabase | なし |
| 使用玉、差玉 | ランキング整合性確認 | Supabase | なし |
| シミュレーター設定 | 端末内の設定保持 | localStorage | あり |
| 体力、持ち玉などの状態 | 端末内のプレイ状態保持 | localStorage | なし |
| 広告関連情報 | 広告配信、広告効果測定 | Google | なし |
| アクセスログ | 配信、保守、不正対策 | Netlify / Supabase / Google | なし |

## Google Play データセーフティ候補

申告候補:

- アプリのアクティビティ
- アプリ情報、パフォーマンス
- デバイスまたはその他のID
- ユーザー生成コンテンツに近い情報としてニックネーム

目的候補:

- アプリの機能
- 分析
- 不正防止、セキュリティ、コンプライアンス
- 広告、マーケティング

注意:

- ニックネームはランキング表示のため公開される
- メールアドレス、本名、住所、電話番号は収集しない
- 広告IDやCookieの扱いはGoogle広告サービスの仕様に従う
- AdMob導入後は、AdMob SDKのデータ取扱いに合わせて再確認する

## App Store プライバシー申告候補

申告候補:

- ユーザーコンテンツ: ニックネームとランキング結果
- 使用状況データ: アプリ内操作、広告表示、分析に関する情報
- ID: 広告IDまたは端末ID相当の情報
- 診断: クラッシュ、パフォーマンス情報

目的候補:

- App機能
- 分析
- 広告
- 不正防止

注意:

- iOSアプリ化時にAdMob SDKを入れる場合、App Tracking Transparencyの要否を確認する
- トラッキングに該当する設定を使う場合は、ストア申告とアプリ内許可導線が必要
- PWAのみの場合とネイティブアプリの場合で申告内容が変わる

## 申告前チェック

- `privacy.html` の内容とストア申告が矛盾していない
- AdSense / AdMobの実際の設定と一致している
- Supabaseで保存しているランキング項目と一致している
- ニックネームが公開されることを説明できる
- 登録画面に個人情報を入力しない案内が表示されている
- AdMob SDK導入後に再確認する
